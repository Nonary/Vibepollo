# Vibeshine 2.0.0-beta.4 - 2026-09-19

Notice: Vibeshine may trigger false-positive antivirus alerts. Details and workarounds are documented here: https://github.com/Nonary/vibeshine/issues/59

## Changes

- Added native DualSense haptic waveform streaming to compatible Moonlight clients, with legacy rumble fallback, and packaged the Linux composite USB controller driver.
- Enabled Proton DualSense compatibility by default, added a toggle in both Web interfaces, and preserved explicit game overrides. Compatible clients now let direct Proton launches wait up to two seconds for the virtual controller and its audio endpoint.
- Added stream-scoped Proton HDR and Wayland HDR compatibility for direct launches and games started through an existing Steam session, with controls in both Web interfaces.
- Limited automatic Steam synchronization to the 10 most recently played installed games by default, after exclusions, with an option to remove the limit. Kept Steam enabled on Linux while honoring library synchronization choices.
- Reduced idle CPU work by suspending host statistics sampling when no stream or live statistics viewer needed it.
- Updated the bundled Windows virtual display driver to version 1.6.3 and refreshed the virtual gamepad package.

## Fixes

- Released held keyboard keys, mouse buttons, controllers, touch, and pen input when clients disconnected, including when capture teardown stalled. Browser viewers now released their own input independently on connection loss.
- Corrected native PlayStation controller initialization, pairing, firmware responses, and motion calibration, and preserved DualShock 4 report sequencing when PS or touchpad buttons changed.
- Preserved existing PlayStation rumble and trigger feedback when games sent partial actuator updates.
- Automatically used the bundled Windows virtual gamepad driver when ViGEmBus was unavailable and reflected gamepad support in the Web UI.
- Removed duplicate Linux virtual-display pacing that could delay frame delivery near the maximum refresh rate.
- Ordered Linux shutdown and upgrade cleanup so the GPU host drained before session clients were retired.
- Restored Steam Big Picture launches through the selected Linux desktop session, including HDR launches, and retained game cleanup when process tracking encountered short-lived processes.
- Accepted otherwise-unprivileged Linux launches with inherited capability bits by clearing those bits before launch.
- Applied requested Windows virtual-display resolutions when DXGI omitted custom modes, and stopped idle recovery from recreating displays after streaming ended or paused.
- Preserved existing Windows virtual-display HDR and scaling settings when no change was requested, without altering reported physical monitor dimensions.
- Detected delayed HDR changes during Windows Graphics Capture sessions.
- Kept Windows installer actions accessible on small or highly scaled screens.
- Supported Lutris database paths containing non-ASCII characters.
- Prevented capture polling from blocking behind busy event and queue producers.
