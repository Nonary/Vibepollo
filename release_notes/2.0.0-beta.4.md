# Vibepollo 2.0.0-beta.4 - 2026-09-22

Notice: Vibepollo may trigger false-positive antivirus alerts. Details and workarounds are documented here: https://github.com/Nonary/vibeshine/issues/59

## Changes

- Added full wireless DualSense support when using Vibepollo with the [VRR Moonlight Client](https://github.com/Nonary/moonlight-qt), including native haptic feedback and adaptive triggers. Both the Vibepollo host and the VRR Moonlight Client must run Linux. Tested with 007 First Light.
- Enabled Proton DualSense compatibility by default, added a toggle in both Web interfaces, and preserved explicit game overrides. Compatible clients now let direct Proton launches wait up to two seconds for the virtual controller and its audio endpoint.
- Added stream-scoped Proton HDR and Wayland HDR compatibility for direct launches and games started through an existing Steam session, with controls in both Web interfaces.
- Restored always-enabled Steam discovery on Linux while honoring library synchronization choices.
- Reduced idle CPU work by suspending host statistics sampling when no stream or live statistics viewer needed it.
- Added a fixed 1000 Hz Windows virtual-display mode for VRR streaming and selected it automatically when the client requested VRR pacing.

## Fixes

- Completed native PlayStation USB initialization on Linux and corrected DualSense firmware responses and output handling for games using libScePad.
- Preserved DualShock 4 report sequencing when PS or touchpad buttons changed.
- Removed duplicate Linux virtual-display pacing that could delay frame delivery near the maximum refresh rate.
- Ordered Linux shutdown and upgrade cleanup so the GPU host drained before session clients were retired.
- Restored Steam Big Picture launches through the selected Linux desktop session, including HDR launches, and retained game cleanup when process tracking encountered short-lived processes.
- Accepted otherwise-unprivileged Linux launches with inherited capability bits by clearing those bits before launch.
- Applied requested Windows virtual-display resolutions when DXGI omitted custom modes, and stopped idle recovery from recreating displays after streaming ended or paused.
- Improved Windows Graphics Capture frame timing and RTP timestamps to follow game presentation more closely, including when capture callbacks arrived unevenly.
- Kept the Linux virtual-display restart safeguard active after the last virtual display was removed.
