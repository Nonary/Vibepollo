# Vibepollo 1.19.0-beta.5 - 2026-09-02

Notice: Vibepollo may trigger false-positive antivirus alerts. Details and workarounds are documented here: https://github.com/Nonary/Vibepollo/issues/59

## Linux requirements
- KDE Plasma 6 on Wayland started by Plasma Login Manager or SDDM. Other desktops and X11 sessions are not streamed.
- Linux 6.16 or newer with headers for the running kernel; the virtual-display module is built with DKMS at install time.
- A GPU with an H.264 hardware encoder. HEVC and AV1 are used when available. Pre-login streaming requires an NVIDIA GPU; AMD and Intel GPUs stream after login.
- Pair Moonlight from either the login screen or a logged-in desktop. Completing a login-screen pairing still requires signing in to Vibepollo's Web UI from another device to submit the PIN.
- The beta is built and tested on CachyOS. Other Arch-based distributions are supported on a best-effort basis. Full instructions: [docs/linux/install.md](https://github.com/Nonary/Vibepollo/blob/master/docs/linux/install.md).

## Changes
- Added `scripts/linux_install.sh`, an Arch/CachyOS installer that checks the requirements, installs the kernel headers for the running kernel, installs the package from the signed repository or the GitHub release, opens firewalld or ufw, and reports whether a reboot is needed.
- Added a Linux installation guide with requirements, manual steps, verification, and troubleshooting.
- Added SDDM-started Plasma Wayland desktops to the sessions the Linux machine host streams, alongside Plasma Login Manager.
- Added firewalld and ufw service definitions for the Vibepollo ports and a PipeWire configuration drop-in with the 240-sample, 48 kHz quantum the audio stream expects.
- Added printed next steps at the end of Linux package installation covering pairing, firewall, and any required reboot, and an explicit Plasma Login Manager or SDDM hint whenever the controller refuses a session.
- Added header package hints for the Arch zen and LTS kernels and the CachyOS LTS kernel.
- Added Resume beside running games in the remote library.

## Fixes
- Fixed the Linux package removing `cap_sys_nice` from KDE's `kwin_wayland`, which cost the compositor its realtime scheduling. The GPU bridge is now a trusted set-user-ID library that the secure-mode loader accepts, the vendor binary is left untouched, and upgrading restores the capability on machines an earlier build changed.
- Fixed first-time Linux installation leaving the machine host disabled: automatic setup now selects the single interactive desktop account instead of requiring a legacy per-user profile, and profile import and command authorization accept a machine with no previous Vibepollo configuration.
- Fixed the Linux host unit referencing a `vibepollo-uinput` group that no package created; the package now creates the group and assigns `/dev/uinput` and `/dev/uhid` to it.
- Fixed the Linux host never reporting ready on GPUs without an AV1 encoder; readiness now requires the H.264 encoder only.
- Fixed the pre-login greeter forcing the NVENC encoder on machines without an NVIDIA GPU.
- Fixed Linux packaging hooks printing Vibepollo setup requirements as easily missed warnings.
- Fixed the Linux machine host running the raw `steam -applaunch` command itself when a game could not be resolved from Steam metadata, which the session broker always refused; it now hands the launch to the Steam client in the desktop session, logs why the resolve failed, and the broker logs which request it rejected.
- Fixed Linux direct Steam launches failing silently when the Steam client is not running (typically after the machine slept); the launcher now starts the client, waits for it to accept commands, and logs its diagnostics to the journal under `vibepollo-steam-launch`.
- Fixed the Linux host refusing to start after its first restart because an earlier build wrote the TLS certificate world-readable and the profile check rejected it; the host now normalizes modes on files it owns and the package repairs the machine profile on install and upgrade.
- Fixed a first-time Arch install failing to start the session controller because the `vibeshine-vkms` group did not exist yet when the control socket was started; the hook now creates both account sets before starting anything.
- Fixed the Arch install hook leaving the host units masked until reboot when it could not choose the desktop user automatically.
- Fixed Moonlight pairing at the login screen by keeping the authenticated Web UI reachable from the LAN and accepting pairing requests before desktop login.
- Fixed a cancelled Moonlight pairing attempt blocking the same client from retrying for ten minutes.
- Fixed Linux upgrades hanging or leaving Vibepollo unable to restart when the running host took longer to stop, the controller was frozen, or stale broker and control sockets survived quiescence.
- Corrected the Arch package's NVIDIA optional dependency: NVENC needs `nvidia-utils` at runtime, not the CUDA toolkit.
- Preserved machine-host display handoffs and isolated resumable app cache identities.
