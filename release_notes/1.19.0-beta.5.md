# Vibepollo 1.19.0-beta.5 - 2026-09-02

Notice: Vibepollo may trigger false-positive antivirus alerts. Details and workarounds are documented here: https://github.com/Nonary/Vibepollo/issues/59

## Linux requirements
- KDE Plasma 6 on Wayland started by Plasma Login Manager or SDDM. Other desktops and X11 sessions are not streamed.
- Linux 6.16 or newer with headers for the running kernel; the virtual-display module is built with DKMS at install time.
- A GPU with an H.264 hardware encoder. HEVC and AV1 are used when available. Pre-login streaming requires an NVIDIA GPU; AMD and Intel GPUs stream after login.
- Pair Moonlight from a logged-in desktop first; the pre-login stream reuses that pairing and does not accept new pairing requests.

## Changes
- Added SDDM-started Plasma Wayland desktops to the sessions the Linux machine host streams, alongside Plasma Login Manager.
- Added firewalld and ufw service definitions for the Vibepollo ports and a PipeWire configuration drop-in with the 240-sample, 48 kHz quantum the audio stream expects.
- Added printed next steps at the end of Linux package installation covering pairing, firewall, and any required reboot, and an explicit Plasma Login Manager or SDDM hint whenever the controller refuses a session.
- Added header package hints for the Arch zen and LTS kernels and the CachyOS LTS kernel.
- Added Resume beside running games in the remote library.

## Fixes
- Fixed the Linux package removing `cap_sys_nice` from KDE's `kwin_wayland`, which cost the compositor its realtime scheduling. The GPU bridge is now a trusted set-user-ID library that the secure-mode loader accepts, the vendor binary is left untouched, and upgrading restores the capability on machines an earlier build changed.
- Fixed first-time Linux installation leaving the machine host disabled: automatic setup now selects the single interactive desktop account instead of requiring a legacy per-user profile, and profile import and command authorization accept a machine with no previous Vibepollo configuration.
- Fixed the Linux host unit referencing a `vibepollo-uinput` group that no package created; the package now creates the group and assigns `/dev/uinput` and `/dev/uhid` to it.
- Fixed the Linux host never reporting ready on GPUs without an AV1 encoder; readiness now requires the H.264 encoder only.
- Fixed the pre-login greeter forcing the NVENC encoder on machines without an NVIDIA GPU.
- Fixed Linux packaging hooks printing Vibepollo setup requirements as easily missed warnings.
- Preserved machine-host display handoffs and isolated resumable app cache identities.
