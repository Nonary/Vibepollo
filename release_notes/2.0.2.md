# Vibepollo 2.0.2

Notice: Vibepollo may trigger false-positive antivirus alerts. Details and workarounds are documented here: https://github.com/Nonary/vibeshine/issues/59

## Changes

- Added Windows VHF support for the 2026 Steam Controller, including its trackpads, motion, and feedback with compatible drivers and clients. Update controller firmware with the controller connected directly to a PC, not over a stream.
- Added optional Dolby Digital (AC-3) and Dolby Digital Plus (E-AC-3) audio for compatible clients and builds with the corresponding FFmpeg encoder. Opus remains the default and fallback.
- Added native RTX HDR for opted-in SDR applications on supported NVIDIA Linux hosts, and extended Windows RTX HDR to PyroWave. Availability depends on compatible hardware and runtime components.
- Added an experimental, opt-in Hyprland machine-service capture path for verified SDR outputs, including Steam and Lutris launch support under its documented conditions.
- Added a Linux desktop companion for host status and control.
- Added optional host adaptive packet pacing for standard video streams. It is disabled by default and does not change encoder bitrate or frame rate.
- Added an optional keyboard binding for the client Guide button, and made automatic Windows keyboard and mouse input prefer the VHF driver when available, with fallback.
- Added a separately granted, default-off permission for compatible paired clients to request host sleep while the host is idle. Added an optional authenticated Windows shortcut to end host streams.
- Allowed built-in Desktop, Remote Monitor, and Remote Input applications to be removed and restored while retaining their settings and artwork.
- Added controls to enable or disable access for individual clients, and support for continuous audio when requested by a compatible client.

## Fixes

- Improved Windows display recovery when monitors wake or return, virtual screens are reused, or a session ends. Saved physical layouts and primary display choices are retained until restoration is verified.
- Fixed Remote Monitor HDR requests and shared-display layout reconciliation, including retries after abandoned or failed launches.
- Preserved the requested stream viewport when an application uses a different display resolution or scaling.
- Improved Windows capture efficiency and fixed recovery keyframe handling, cursor visibility, and capture behavior after output changes.
- Fixed virtual controllers failing to recover after device removal, retaining the latest input and battery state through reconstruction. Improved reconnect cleanup to avoid stale remote input sessions.
- Fixed Steam library discovery from Windows service sessions, respected explicit Proton selections and direct-launch working directories, and improved Playnite connector recovery.
- Fixed Linux capture issues affecting KWin 6.8 and AMD buffer layouts, and improved launch handoff after application shutdown.
- Fixed Arch package transaction shutdown and recovery while preserving administrator hooks and service masks.
- Fixed pairing-state import and recovery cases, including duplicate legacy client records; restored terminal-based pairing; validated existing records when a client re-pairs; and made Windows state replacement more durable.
- Preserved the active application list when a reload or legacy migration fails, and prevented malformed application lists from being rewritten as empty.
- Fixed installer display-driver inventory timeouts and locale-sensitive checks, and hardened privileged Windows helper and installation boundaries.
