# Vibepollo 2.0.0-stable.1 - 2026-10-05

Notice: Vibepollo may trigger false-positive antivirus alerts. Details and workarounds are documented here: https://github.com/Nonary/vibeshine/issues/59

## Changes

- Added optional wired USB DualSense emulation on Windows for native waveform haptics. Compatible games can see a controller with both USB HID and audio endpoints and send detailed actuator feedback through a compatible Moonlight client. Select **DualSense USB audio and haptics** in the Windows x64 installer, then enable **DualSense waveform haptics** for an application or select `usbip_ds5` globally under Input settings. The optional component is off by default, uses Microsoft-signed usbip-win2, and may require a restart. This feature requires a game with native DualSense support and a client that supports waveform feedback on a physical DualSense; ordinary rumble remains available with the other gamepad profiles. See the [Windows DualSense haptics guide](../docs/windows-dualsense-haptics.md) for setup and compatibility details.
- Increased the configurable virtual-display client limit from four to eight on Windows and Linux. Normal game sessions and Remote Monitor sessions from the same paired client share a display slot. The default remained four; set `virtual_display_max_clients` to a value from `1` to `8` to change it. New Linux display pools provision eight outputs and accept client modes and rotations across all eight. Existing four-output Linux pools are preserved during upgrades; reboot or safely reprovision with the host and compositor stopped before requesting more than four clients. See the [display-capacity instructions](../docs/configuration.md#virtual_display_max_clients).
- Added virtual-screen recovery to the dashboard, with status, explanations, and a recovery action for screens left behind after a failed session. Display recovery also gained monitor-wake and topology-event handling, allowing cleanup to resume when a physical display becomes usable and no active session owns the affected screen.
- Added a Linux virtual-display termination control in Maintenance. It attempts to restore the physical desktop, removes managed virtual outputs, and reports output removal separately from desktop restoration. The interface explains when removal succeeded but restoration still needs attention. This action interrupts video on sessions using those outputs.
- Added saved relative display arrangements for Windows clients. **Devices → Arrange client displays** lets users choose placement direction, alignment, and spacing, or preserve a manually arranged layout. Saved placement is applied to supported extended-display sessions and retained for later connections.
- Added shared automatic focus settings for managed Steam, Lutris, and Playnite launches on Windows, Linux, and macOS. Vibepollo retries while the game window appears and stops when its session ends. The default policy makes three confirmed focus attempts within 15 seconds; setting the attempt count or timeout to zero disables it. Existing Playnite focus settings remain accepted for compatibility. Manual applications and Desktop launches are excluded.
- Added a Playnite installation-directory setting on Windows for installations that automatic detection misses, including portable installations. Updated the Playnite 10 connector with library notifications and launch/reconnect handling. Playnite 11 requires a separate compatible connector.
- Added paced UDP bandwidth calibration for paired PyroWave clients. The probe establishes an authenticated UDP return path before measurement, checks delivery loss and stability, and confirms a lower rate when necessary, rather than relying only on HTTPS download throughput. Compatible clients receive the host's critical FEC overhead so recommendations can reserve bandwidth for parity, audio, control traffic, and packet overhead. Older clients retain the HTTPS probe. PyroWave still requires a fast wired LAN and a compatible [Nonary VRR Moonlight Client](https://github.com/Nonary/moonlight-qt); calibration must run while no stream is active and does not measure actual game smoothness.
- Added Windows host-service startup controls to Troubleshooting/Maintenance in both Web UIs. Disabling automatic startup sets the installed service to Manual, leaving manual launch available and an existing session running. The interface reports the actual service mode and explains permission or missing-service failures.
- Expanded Everyday settings into a grouped setup workflow for displays, smoothness, PyroWave, and Remote Monitor, with shortcuts to detailed controls and supported game-library integrations. Everyday and detailed settings share the same pending edits. Windows and Linux show the controls appropriate to their platform.

## Fixes

- Fixed Windows display recovery losing its restore request after a broken helper connection. Active streams can renew their own display ownership, while stale connections no longer cancel recovery for another session. Recovery can continue after the owning connection disappears.
- Fixed saved Windows layouts being replaced by a partially restored arrangement. Restoration now checks the full topology and requested resolution/refresh modes before saving primary-monitor and position changes. Equivalent fractional refresh rates are recognized correctly, and failed restoration retains the saved layout for retry.
- Improved recovery when a physical monitor returns after a fallback restore. Vibepollo retries the authoritative saved layout when its missing monitors become available, preserves monitor-return events through failed recovery attempts, and respects the configured golden-first recovery preference.
- Fixed Remote Monitor teardown changing or removing a display while RTSP or WebRTC capture still used it. Cleanup waits for capture ownership to drain, protects other clients' displays, and retains failed native removal for retry. Ending a game no longer releases a display still needed by a retained remote session.
- Fixed **Disconnect Monitor** leaving an owned Windows virtual screen behind when restoring the remaining monitor layout failed. The exact client's screen can now be removed independently of that restore, while other clients and active captures remain protected.
- Fixed possible Windows Graphics Capture crashes during display reinitialization and HDR changes. Teardown now drains frame callbacks before releasing capture resources, and pending helper handshakes can be canceled during shutdown.
- Fixed Windows capture starting or resuming before display setup completed, including WebRTC sessions. Capture now waits for the display apply result instead of probing during the helper's temporary SDR setup, avoiding an incorrect initial HDR/SDR capture path.
- Fixed live Windows HDR/SDR changes leaving the stream permanently forced into HDR. Confirmed output color changes now trigger capture reinitialization so stream color state can follow the display.
- Fixed Windows HDR calibration being overwritten when shared Vibeshine driver displays were reused or routed to another client. Driver-owned calibration associations are retained automatically; the client HDR profile override remains available for physical displays and other virtual-display drivers. Failed native profile activation no longer leaves a competing registry-only association, and successful activation no longer performs a redundant second activation.
- Shipped the Windows virtual-display driver's HDR gamut correction. HDR display descriptors now advertise BT.2020/D65 primaries instead of Rec.709, while SDR descriptors retain their existing color information.
- Fixed missing HDR Vulkan-layer coverage for 32-bit Windows games. The installer now includes and registers both 32-bit and 64-bit layer payloads in their matching registry views, with checks against partial or mismatched installations.
- Fixed Windows virtual-display refresh mappings being matched against an automatically promoted capture rate instead of the requested stream rate. Manual and mapped refresh choices now take precedence consistently without changing the game limiter or stream FPS. Automatic high-refresh modes respect the display-mode ceiling on Windows 10 and Windows 11 versions before 24H2 instead of requesting unsupported rates.
- Fixed Xbox clients being emulated as DualSense through the Windows VHF backend when they reported motion sensors or a touchpad. Xbox client identity now takes precedence over those capabilities, while explicit gamepad-profile selections still win.
- Shipped the virtual-gamepad driver's DualSense identity correction for Windows GameInput. The device now reports its native Sony identity instead of `0000:0000`, improving identification by applications that match GameInput and HID devices.
- Fixed repeated Windows input-injection failures trapping the input worker in an unbounded retry loop during desktop transitions. Desktop bindings are retained and released safely, and recovery is limited to one retry after a successful bind.
- Fixed Windows audio-role recovery being discarded when Steam audio visibility recovery failed. Original playback roles remain queued for restoration when the endpoint returns, while newer user-selected defaults are preserved.
- Kept the Linux Web UI responsive while display layouts are queried or restored, including recovery after resume. Display restoration runs in the background and retains failed recovery state for later attempts.
- Improved Linux desktop restoration after stream teardown and host crashes. Saved recovery intent survives restart and connector retirement, idle layouts are not overwritten by stale recovery data, and managed outputs are retired after a physical display is ready. Paused applications and retained Remote Monitor sessions keep their display ownership.
- Fixed Linux monitor and TV restoration being confused by virtual outputs in the saved desktop layout. New snapshots contain physical outputs only, existing snapshots are sanitized, and a virtual screen is no longer treated as the physical restore guard.
- Fixed Linux multi-display setup and restoration rejecting complete requests for larger HDR layouts. Requested modes are accepted when a managed display's public name is shifted by another DRM device, such as `Virtual-9` or `Virtual-10`. SteamOS local display control now maps those names to the correct managed output.
- Fixed AMD virtual-frame readback on Linux hosts whose display-only DRM device cannot provide a renderer, including packed-color channel ordering. Improved multi-GPU display routing to preserve Virtio console rendering and avoid treating imported buffers with unknown layouts as ordinary linear CPU-readable frames.
- Fixed Linux virtual-display routing overriding an explicitly selected capture method. Automatic selection still prefers KMS for managed virtual outputs; an explicit alternative is honored with a compatibility warning.
- Fixed Linux installation and machine setup failing under translated locales or an inaccessible caller working directory. Validation no longer depends on English file-type descriptions, recovery operations run from a usable directory, and upgrades can repair an incomplete setup while preserving the existing profile and pairing state. The installer also verifies the installed private host's required capabilities before reporting success.
- Fixed Steam/Proton discovery treating Pressure Vessel's `/run/host/` paths as literal host paths, preventing valid Proton and Steam installations from being found. Global limiter policy injection now skips read-only, system-owned Proton tools instead of failing with permission errors, while continuing to manage writable user-owned tools.
- Fixed PyroWave encoder compatibility with Intel GPUs on Windows by checking the D3D11/Vulkan interoperability features the encoder actually uses.
- Fixed PyroWave traffic exceeding the negotiated wire-bandwidth budget. Frame payloads and pacing now reserve space for critical FEC, audio, control traffic, and packet overhead rather than treating the configured rate as codec payload alone.
- Preserved user-disabled Windows display-restore scheduled tasks instead of recreating or deleting them during recovery. Recovery settings remain visible when display automation is disabled, and the Web UI explains unavailable actions using current maintenance status.
- Fixed the new Web UI's display-state reset action not following fetched maintenance availability. Status retries update the related recovery controls together, and unavailable recovery operations stay disabled.
- Corrected Windows frame-limiter choices and standard FEC validation in Everyday settings. Unsupported saved limiter choices remain visible without being silently rewritten. An unchanged legacy standard FEC value of zero no longer blocks saving unrelated settings; new standard FEC values must be `1`–`255`, while PyroWave critical FEC still permits zero.
