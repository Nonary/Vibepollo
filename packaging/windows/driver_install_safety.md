# Driver installation safety

Windows display, legacy SudoVDA, and VHF gamepad installation compare the candidate INF's numeric four-part DriverVer component version with active CIM DriverVersion values and matching Driver Store INF versions. INF dates, application versions, release tags and artifact timestamps never decide whether to replace a component. An equal or newer active or staged component is retained. Missing metadata, unreadable INF files and failed inventory queries block changes.

A missing component or genuinely newer candidate is installed only when its catalog has an intact Windows-trusted signature. Display and SudoVDA catalogs also require a non-self-signed signer. VHF self-signed artifacts are explicitly supported when Windows already trusts the catalog and the setup tool; the bundled certificate identity must match both. Unsigned and untrusted packages are blocked with a manual security review warning; the existing component remains installed. The local-test override does not authorize automatic certificate imports. Self-signed drivers may require additional certificate trust or weakened boot/signing policy; the installer never adds local-test roots, enables test signing, or changes Secure Boot. Stable production publisher handling remains behind the guard with DailyUnsignedPolicy=0. The daily MSI passes DailyUnsignedPolicy=1, disabling production publisher imports too. Self-signed VHF packages use no production publisher import path in either lane.

Before stopping driver services or removing existing nodes, Windows stages and verifies the candidate catalog members. SudoVDA staging failure therefore preserves its existing node. Bootstrapper MSI pre-uninstalls set UPGRADINGPRODUCTCODE to preserve shared driver devices; legacy non-MSI migrations fail safely when that preservation cannot be guaranteed. Explicit user-requested uninstall behavior remains available.

USB/IP uses the pinned, original Microsoft-signed package and retains existing shared devices, services and staged packages. It does not import test certificates or invoke the vendor's destructive upgrade installer. ViGEm is not replaced by the new VHF component installer.

Run `powershell -NoProfile -File packaging/windows/test_driver_install_safety.ps1` before publishing a daily artifact. The test parses installer scripts, extracts only read-only policy functions, mocks all system inventories and signatures, checks missing/older/equal/newer cases for trusted/unsigned/untrusted/self-signed candidates, query failures and unknown versions, and tests failed SudoVDA staging without executing a driver installer. Publication should additionally compare extracted MSI installer script hashes with this source to verify the tested policy is actually shipped.
