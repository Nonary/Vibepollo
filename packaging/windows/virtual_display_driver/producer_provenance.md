# Windows display producer provenance

The reviewed Windows payload is libvirtualdisplay v1.6.4, source `2a29ea71a52d15522c95b3de532b6612c54d75cc`, archive SHA-256 `34c6cddb507187b9a0971765644b38637004d7ebed104e830363f36b661ed075`, actual INF `DriverVer=10/04/2026,1.6.4.0`. `third-party/libvirtualdisplay-release/windows-x64.json` pins its evidence JSON, producer signing identity and every archive file. The upstream release is mutable and self-signed; these pins establish reviewed source/bytes, not Windows installation trust or immutable-release status.

Fresh downloads resolve the annotated tag to the locked source, require matching API asset digests, hash the downloaded archive/evidence, check exact ZIP paths/inventory, and verify every extracted file and real INF version before publishing a cache. Existing caches require the same locked payload hashes plus evidence and consumer metadata. Missing, changed, incomplete or extra cached files fail without replacement. Explicit CMake prebuilt directories and direct package refresh are also validated. Previously unverified caches require a fresh verified download into a new directory; they are never automatically accepted from file existence.

The Windows payload source intentionally differs from the Linux source gitlink `1b8524e20ebef1db5d5c063a130a1ebb49aafab0`, which retains subsequent Linux fixes. Product packaging copies the reviewed x64 driver/INF/catalog byte-for-byte; its source checkout is used for the separate x86 Vulkan layer. Preserve the later Linux gitlink when updating this Windows producer lock. Update source, asset/evidence hashes, all payload hashes and actual INF component version together following explicit producer review. Do not infer component versions from tag dates or the source-tree development INF.

Display installation compares numeric component versions before signer or trust changes: equal/newer installed components are retained and unknown inventories fail safely. Missing/older drivers may install the reviewed self-signed release only after pinned certificate identity, public-certificate policy, signed INF hardware identity and independent CMS/catalog membership checks pass. Eligible expected self-signed candidates provision only their exact public certificate into LocalMachine Root and TrustedPublisher; existing trusted production catalogs preserve their expected publisher identity and add only TrustedPublisher. Failed provisioning or pre-replacement Windows staging rolls back newly added trust, preserving pre-existing certificates and drivers. Windows staging and loading remain authoritative; no Secure Boot, test-signing or signature-enforcement changes are made. This does not invoke SignPath or change stable release signing. Daily continues using hosted runners without SignPath.

Run `scripts/tests/test_display_producer_provenance.ps1` for mocked fresh/reused cache tamper coverage; the mandatory driver safety suite includes it. Tests use synthetic inert payloads and mock networking. The production lock was additionally validated against read-only public artifacts; no signing keys, trust-store changes, installers, drivers or services are exercised.
